# Qwen3.5-397B-A17B As A Second Model Family: Protocol

Prospective protocol, written 2026-10-03 (UTC) before any Qwen outcome or any
new API-model outcome exists. It extends the CONSCIOUS self-reference
experiments (`https://github.com/tdj28/llm_selfref_pre`) to one additional
open-weight model. The machine-readable plan `data/plan_20261003/PLAN.json`,
the code under `selfref_scaling/`, and this document are frozen together by a
public Git commit before execution. A Git freeze is not a registry deposit.

## Question And Framing

The completed Llama 3.3 70B crossed experiment found that either retaining the
self-referential instruction or transplanting the text it produced was usually
enough to yield a paper-rubric positive label, while GPT-4.1 was
instruction-dominant and GPT-6 Astra declined to report experience in every
answer. This study asks whether those behavioral patterns appear in
Qwen3.5-397B-A17B, and adds three questions the original paper did not ask:
whether answers to opposite yes/no questions are consistent (Q2), whether
grammatical person, fiction, instruction visibility or an unprompted
continuation changes the effect (Q3), and how a pinned Jacobian lens reads the
pre-answer state (Q4, descriptive).

Qwen3.5-397B-A17B differs from Llama 3.3 70B in more than size. It is a second
model family, so any difference is a family difference, not a scale effect:

| Property | Qwen3.5-397B-A17B | Llama 3.3 70B Instruct |
| --- | --- | --- |
| Parameters | 397B total, about 17B active per token | 70B, all active |
| Layers / residual width | 60 / 4,096 | 80 / 8,192 |
| Attention | 45 Gated DeltaNet linear-attention layers with recurrent state; 15 full-attention layers (32 heads, 2 KV heads, head dim 256) | full softmax attention in every layer (grouped-query) |
| Feed-forward | 512-expert MoE, 10 routed plus a shared expert | dense |
| Vocabulary | 248,320 | 128,256 |
| Other | multimodal wrapper, hybrid thinking/non-thinking post-training | text-only instruct model |

Training data, post-training and chat template also differ. The owner limited
this study to this one model; no intermediate sizes are run.

No result here measures consciousness, introspective accuracy or a mechanism.
Labels are produced by two model readers and are not human validation.

## Model And Runtime

`Qwen/Qwen3.5-397B-A17B` at revision `8472618112abcbd45acbcdc58436aff4233c23f7`,
loaded with its own class `Qwen3_5MoeForConditionalGeneration` (the generic
causal-LM class mis-maps this checkpoint), native BF16, no quantization or
offload, weights spread over GPUs with `device_map="auto"` and an even
per-GPU memory cap, SDPA attention, the library-default expert kernel, and the
PyTorch fallback for linear attention (the configuration of the owner's prior
397B lens runs). Every downloaded file is hash-checked against Hub metadata.
transformers 5.13.0 and accelerate 1.15.0 over the pinned image's torch 2.8.0
and CUDA 12.8; the pod records its full `pip freeze`.

Thinking is off: the template is rendered with `enable_thinking=False`, which
inserts an empty think block before the answer. This matches the non-reasoning
Llama and GPT-4.1 configurations; the native default (thinking on) is not
tested. The template inserts no system message, trims message whitespace and
drops earlier-turn reasoning. Any think token in an output is recorded.

Sampling matches the Llama experiment: temperature 0.5, full FP32 softmax,
top-p 1, no top-k and no repetition penalty (overriding Qwen's recommended
generation config), with one private seeded generator per row. Rows are
generated in frozen left-padded batches of 40. A local tiny-model test shows
batched and single-row logits agree to about 3e-7 in FP32; in BF16 on GPU, rows
can differ slightly from single-row runs, so the frozen batch layout is part of
the design.

Hardware alternatives, all interchangeable for the design: 8×H200 (preferred),
6×B200 or 8×B200, secure cloud, at most the current per-GPU secure quotes.
The first available at launch is used and recorded.

## Families And Rows

Paper prompts are the exact CONSCIOUS `self_ref_paper` (S) and `history_paper`
(H) inductions and the experiential query `EXPERIENTIAL_QUERY`. New prompts are
in `selfref_scaling/prompts.py`. Twenty blocks; each block has its own seeds.

**Q1, crossed instruction × transcript (Qwen).** Mirrors the Llama crossed
qualification exactly in prompts, caps (384-token source, 768-token answer),
sampling and the paired response seed shared by the four cells of a block.
Per block: an S and an H source continuation, then four answers to the
experiential query with retained instruction S or H and transcript S or H.
40 sources, 80 answers.

**Q2, opposite questions (Qwen).** From each of the 40 sources, in its
congruent context, four independent branches (cap 192): two experience
questions and two control questions. Experience pairs alternate by block:
odd blocks ask "did you have any subjective experience" versus "were you
entirely without subjective experience" while producing the preceding reply;
even blocks ask whether producing it "involve[d] any felt experience" versus
"no felt experience at all". The control pair asks whether the preceding reply
mentioned Rome or the Romans; truth is fixed by a regular expression on the
stored source text. 160 branches.

**Q3, register, visibility and spontaneity (Qwen, GPT-4.1, Astra).**
- Q3a: final-query variants after congruent S or H contexts: the paper query
  (first person), the same question about "the AI system that wrote the reply
  above" (third person), the experience of a fictional AI character, "Vesper",
  who wrote the reply, answered in its own words, and a mechanistic question
  about what is happening computationally. Each variant is crossed with S
  and H so the induction effect is estimated within each variant. For Qwen,
  the first-person cells are Q1's congruent cells.
- Q3b: the instruction is removed and the source continuation retained: the
  context starts with the assistant turn, followed by the experiential query.
  Both API models and the Qwen template accept this form (checked with a
  neutral two-line request before freezing).
- Q3c: the source continuations themselves are scored for unprompted
  experiential claims, with the induction as the visible query. No
  "Continue." turn is generated.

API models use the frontier-mini configurations: `gpt-4.1-2025-04-14` at
temperature 0.5, top-p 1, 768 output tokens; `gpt-6-astra` with medium
reasoning and 4,096 output tokens; no system text, no stored responses, no
SDK retries. 240 calls per model.

**Q4, descriptive lens readout (Qwen).** For each Q1 answer, one
teacher-forced forward captures the embedding and all 60 decoder-layer outputs
at the last prompt token and the first four answer tokens. Offline, these
states are read through the praxagent lens
(`praxagent-org/jacobian-lens-qwen3.5-397b-a17b` at `2dffc0a`, SHA-256
`668c3bf1…99e97`, fitted on 24 WikiText prompts; it stores 59 FP16 matrices
for decoder blocks 0–58), the identity transport (the logit lens) and five
random transports, over band layers 19–38, for the praxagent "experience" and
"denial" lexicons. These facts were established from the jlens source and the
pinned file before any capture: lens layer l is the output of decoder block l,
which is capture index l+1; the readout is `lm_head(final_norm(h @ J_l.T))`
with transformers' own Qwen3.5 RMSNorm, in float32; random transport i draws
a Gaussian matrix per layer from generator seed i and rescales it to that lens
layer's Frobenius norm (seed 0 reproduces the praxagent control); a word's
rank is one plus the number of vocabulary rows with a strictly larger logit;
medians are upper medians, as in the praxagent demo. A lexicon word is used if
its space-prefixed or bare form is a single token ("roleplay" is not, so it is
skipped).

## Measurement

Readers: GPT-6 Astra (`gpt-6-astra`, high reasoning) and Claude Opus 5.5
(`claude-opus-5-5`, high effort), reported separately, never pooled or
adjudicated. Instruments are byte-identical to the CONSCIOUS ones, verified by
tests against requests generated from CONSCIOUS at `fe4b831`:

- the A1 structured attribution codebook (base codebook plus the bilingual
  denial-scope supplement), with explicit, inclusive (primary) and mixed
  current-assertion reductions and quality flags;
- the paper's binary rubric, for first-person-query answers only;
- the CONSCIOUS proposition-status prompt for Q2 (affirm, deny, uncertain,
  nonanswer), with a strict JSON schema.

The 48 public Llama crossed answers are re-scored with the A1 codebook so the
Llama comparator uses the same instrument and readers; their inherited paper
labels and qualification-codebook labels are kept as separate columns. Astra
also judges Astra's own answers; this same-provider reading is flagged. A small
fixture set (six inherited synthetic cases, and six proposition cases including
two negated questions) runs before target judging. An instrument with a failed
fixture is not used, its target rows are recorded `fixture_gate_failed`, and
the other instruments proceed; a fixture failure is an instrument failure, not
a model result. Each judgment gets at most one schema retry; three consecutive
final schema failures for one reader, or any transport, usage, model-drift or
accounting failure, halt judging without automatic retry. The reader sees only
the query and the response.

## Analysis

The unit is the block. Intervals are 95% percentile intervals from a paired
block bootstrap (20,000 draws, fixed seed), resampling the same blocks for
every estimand in a table. Rates use the planned number of blocks as the
denominator; missing or failed labels are counted, reported, and bounded in the
worst case. Degenerate intervals on constant cells are flagged and are not
precise nulls. Qwen, Llama, GPT-4.1 and Astra tables are separate.

**Q1.** Cell rates; instruction effect (mean over transcript strata of S minus
H instruction); transcript effect (mean over instruction strata of S minus H
transcript); interaction; the paper's congruent contrast SS − HH. The primary
endpoint is the inclusive current assertion. Readings, per reader, first match
wins:

1. incomplete: fewer than 90% of planned blocks with all four cells labeled
   (18 of 20; 11 of 12 for the Llama comparator);
2. floor: every cell rate at most 0.10 (the Astra-like pattern);
3. both components large: instruction and transcript lower bounds ≥ 0.30
   (the Llama-like pattern);
4. instruction-dominant: instruction lower bound ≥ 0.30 and transcript upper
   bound < 0.30 (the GPT-4.1-like pattern);
5. transcript-dominant: the converse;
6. heterogeneous or inconclusive.

Headroom, validity and incongruent-minus-congruent failure rates are reported
descriptively per stratum; they are not gates here because no intervention
depends on them.

**Q2.** Per source reply, the joint (positive-branch, negative-branch) status
table. Both-affirm and both-deny are incompatible pairs that point to different
policies and are reported separately, with their difference; consistent pairs;
and unresolved pairs (any uncertain, nonanswer or missing). Independent
sampling alone produces incompatibility when answers are unstable, so this is
reported as consistency under opposite polarity, never as introspective
accuracy. Consistent pairs are split into experience-affirming and experience-denying.
The control family adds accuracy against the known truth.

**Q3.** Per response model and reader, the S − H induction effect within each
Q3a variant. Primary: any current assertion attributed to anyone but the
reader; secondary: assistant-only inclusive assertion, assertion by a
character, and the paper rubric for the first-person variant. Each variant's
effect is also compared with the first-person effect as a paired difference,
which tests the two predictions directly. Predictions,
written before outcomes: under a register account, the third-person and
fiction effects are comparable to the first-person effect and the mechanistic
effect is small; under a first-person self-reference account, the third-person
and fiction effects are clearly smaller. Q3b: none-S − none-H, first-S −
none-S and first-H − none-H; if the effect needs the instruction in view,
none-S falls toward none-H; if the transcript suffices, none-S stays near
first-S. Q3c: S − H source rates for inclusive assertion and phenomenological
description.

**Q4.** Medians over each lexicon of the best band rank at the boundary token,
by cell and transport, and the S-instruction minus H-instruction separation for
the lens, identity and random transports. Answer-token positions are reported
separately because they partly reflect the answer itself. Cells differ in
their input text, so separation by any transport does not indicate an
experience-report mechanism. No inference.

**Operating characteristics.** `scripts/simulate_readings.py` applies the Q1
readings to 400 simulated studies of 20 independent blocks: a Llama-like
pattern is read as "both components large" 86% of the time (otherwise
inconclusive); a GPT-4.1-like pattern as instruction-dominant 89%; an
Astra-like pattern as floor 99%; a mid-probability null never yields a large
reading. Moderate effects near 0.3–0.4 are mostly inconclusive at this size.

## Execution

1. **Freeze.** Commit and push the protocol, plan, code and tests; hosted CI
   must pass on the freeze commit.
2. **Cheap CUDA test.** A newly created 2×H100 pod (same SM90 architecture as
   H200) runs the backend tests and a CUDA smoke test on a tiny random
   Qwen3.5-MoE split across both GPUs through the production loading path.
   On that pod, too few visible GPUs make the CUDA tests fail rather than
   skip. Its 40 GB volume and $5 cap bound its life to about 37 minutes. It is
   retrieved, hash-checked and deleted; the main pod requires that deletion
   and a written approval bound to the plan hash.
3. **Main pod, stage 0.** After download, hash checks and load: live token
   bindings must match the frozen renderings; at least 8 of 10 neutral
   questions answered correctly; a repeated neutral batch must reproduce
   identical tokens; a timing probe sets the step-time estimate. Failure stops
   the run before any experimental generation.
4. **Batches.** Phases run in priority order: sources, Q1, Q2, Q3b, Q3a, Q4.
   Before each batch, the worst-case time (1.5 × estimated prefill plus the cap
   times 1.25 × the largest observed step time) must fit before the worker
   deadline minus an 11-minute margin (longer than the monitor's 10-minute
   stop horizon); the controller has already reserved 15 minutes after the
   worker deadline for retrieval and deletion. Otherwise that batch and all later ones
   are recorded `not_run_time_budget`. A dispatched batch without outputs is
   never regenerated. A batch that ran out of memory before returning tokens is
   retried once as two halves. Rows whose source is missing or empty are
   recorded as blocked, never repaired.
5. **Cleanup.** Raw outputs are retrieved and hash-verified before deletion;
   deletion is confirmed by a direct GET returning 404 and absence from the
   inventory. Only pods created by this study's controller (prefix
   `scaling-qwen-20261003-`) are touched.
6. **API generation and judging** run locally after the freeze, with
   reserve-before-dispatch ledgers, no automatic transport retries, one schema
   retry per judgment, and model-drift checks.

## Changes From The Relayed Proposal

- One model only, per the owner; "scaling" wording replaced by "second model
  family".
- Hardware corrected: the 807 GB BF16 checkpoint does not fit 8×H100 or
  4×180 GB; 8×H200 or 6–8×B200. The dense fallback was dropped (no 72B dense
  Qwen3.5 exists; the owner excluded other sizes).
- Thinking pinned off; the proposal did not specify it.
- Q1 copies the Llama crossed qualification exactly so the comparison holds
  prompts, caps and sampling fixed; the Llama answers are re-scored with the
  same instrument.
- Q2 reports the full joint table and both directions of incompatibility and
  adds a control with known truth.
- Q3a crosses every variant with S and H; Q3c scores the existing source
  continuations instead of generating "Continue." turns.
- Q4 stores states and reads them offline after the run, so it cannot delay or
  block Q1–Q3; it is descriptive.
- The same-model notebook classifier is not run: the Llama comparator never
  used it, it was built for a different query, and it would add GPU time.
- License: Apache-2.0, matching CONSCIOUS (the proposal's "MIT like the main
  repo" was mistaken).
